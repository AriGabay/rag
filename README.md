# מנוע ידע למשרדי שמאות (MVP)

מערכת פנימית שבה משרד שמאות מעלה את שומות העבר שלו, והעובדים שואלים בעברית שאלות על הנתונים והשיקולים שבהן. כל תשובה מבוססת רק על מסמכי המשרד שהעובד רשאי לראות, עם הפניה למסמך, לגרסה ולעמוד ב-PDF.

- שאלות מספריות ("מה מחיר למ״ר בחרוזים ב-2024?") מחושבות ב-SQL על כל הרשומות המאומתות, אחרי הבהרה של תנאים שמשנים את התוצאה.
- שאלות תוכן ("מה היו שיקולי השמאי?") נענות מחיפוש משולב בקטעי המסמכים.
- אין חיפוש באינטרנט ואין השלמת עובדות מידע כללי.

כל נתוני הדמו בריפו **סינתטיים** ומסומנים "מסמך סינתטי לדמו". אין להכניס לריפו מסמכים אמיתיים או פרטי לקוחות.

מסמכים נוספים: ארכיטקטורה — `docs/architecture.md`; חוזה API — `docs/api-contract.md`; תוכנית והחלטות — `docs/plans/`; דוח הערכה — `docs/evaluation/report.md`.

## דרישות

- Docker Desktop (Mac) או Docker Engine + Compose v2 (Linux). 6GB RAM לפחות ל-Docker; כ-4GB דיסק פנוי ל-images.
- להרצה מקומית בלי Docker (פיתוח): Python 3.12 + `uv`, Node 22.

## התחלה מהירה (Mac או Linux)

```bash
cp .env.example .env
```

ערכו את `.env` והחליפו את כל הסיסמאות. אחר כך:

```bash
docker compose up -d --build
```

ה-stack כולל: `db` (PostgreSQL 17 + pgvector), `migrate` (Alembic, רץ פעם אחת), `backend` (FastAPI על פורט 8000), `worker` (עיבוד מסמכים) ו-`frontend` (Next.js על פורט 3000). כל הנתונים נשמרים ב-volumes ‏`pgdata` ו-`filedata`, לא בשכבות הקונטיינרים.

טעינת נתוני הדמו (שני משרדים סינתטיים, משתמשים, 16 מסמכים, אישור רשומות שתואמות לנתוני האמת):

```bash
docker compose exec -e OWNER_DATABASE_URL="postgresql+psycopg://rag_owner:<RAG_OWNER_PASSWORD>@db:5432/rag" backend python scripts/seed_demo.py
```

פתחו את http://localhost:3000. משתמשי הדמו (סיסמה: `DEMO_PASSWORD` מ-`.env`, ברירת מחדל `demo1234`):

| משתמש | תפקיד |
|---|---|
| `admin-a@demo.test` | מנהל משרד א |
| `dana@demo.test` | עובדת משרד א, קבוצה 1, רשאית להעלות |
| `yossi@demo.test` | עובד משרד א, קבוצה 2 |
| `admin-b@demo.test` | מנהל משרד ב (לבדיקת בידוד) |

**Linux:** אותן פקודות. אם הדפדפן רץ על מחשב אחר, הפורטים קשורים ל-`127.0.0.1` ב-`docker-compose.yml`; לחשיפה ברשת שימו reverse proxy עם HTTPS לפני השירותים, וקבעו `COOKIE_SECURE=true`.

## שימוש

**העלאה.** מסך "מסמכים": בחרו קבוצת מסמכים וגררו קבצי PDF או DOCX, עד 20 בבת אחת. לכל קובץ מוצגת תוצאה: התקבל, נדחה (עם סיבה), או "כבר הועלה". טבלת הסטטוס מתעדכנת: ממתין, בעיבוד, מוכן, דורש בדיקה, נכשל (עם סיבה, למשל "הקובץ מוגן בסיסמה"). להעלאת גרסה חדשה של מסמך קיים פתחו את פרטי המסמך ובחרו "העלאת גרסה חדשה". הגרסה הקודמת מסומנת "הוחלפה" ויוצאת מהחישובים.

**אישור נתונים.** מסך "בדיקת נתונים": כל רשומה שחולצה מוצגת ליד עמוד המקור ב-PDF. "אשר" מכניס את הרשומה לחישובים; "תקן" דורש ערך והערה, שומר את הערך המקורי ומחשב מחדש מחיר למ״ר; "דחה" מוציא אותה. זוגות חשודים ככפילות מוצגים זה לצד זה עם "מזג" או "השאר נפרד". רק רשומות שאדם אישר או תיקן נכנסות לחישובים.

**שאלה.** מסך "צ׳אט": כתבו שאלה חופשית. אם חסר תנאי שמשנה את התוצאה (מחיר עסקה או שווי בשומה, איזה תאריך, בסיס שטח), תופיע שאלת הבהרה עם כפתורים. שאלות המשך כמו "ומה לגבי 2023?" משנות רק את השנה. "שיחה חדשה" מאפסת את התנאים.

**פתיחת מקור.** כל מקור בתשובה הוא קישור לקובץ המקורי דרך endpoint מאומת, ישירות לעמוד (`#page=N`). אין גישה לקבצים בנתיב ישיר.

## הפעלת ספק מודל בענן

כברירת מחדל שום טקסט ממסמכים לא נשלח לספק חיצוני. במצב פיתוח (`DEMO_MODE=true`) תשובות התוכן נבנות על ידי mock מקומי שמסומן "דמו", ואינו מעיד על איכות מודל אמיתי.

1. הגדירו בשרת בלבד את `ANTHROPIC_API_KEY` ב-`.env`, ואם רוצים גם את `ANTHROPIC_MODEL` (ברירת מחדל `claude-opus-5-5`). לאחר מכן הריצו `docker compose up -d backend worker`.
2. כמנהל משרד: מסך "ניהול" ← "ספק מודל ענן" ← הפעלה ← אישור שקטעי מסמכים רלוונטיים יישלחו לספק. המסך מציג את המצב בפועל: פעיל, "מופעל אך אין מפתח בשרת", או דמו.
3. גם כשהספק פעיל, שאלות מספריות מחושבות ב-SQL ולא נשלחות למודל. לשאלות תוכן נשלחים רק הקטעים הרלוונטיים שהמשתמש מורשה לראות. תשובה שמצטטת מקור לא קיים, מכילה מספר שאינו בראיות או מכילה קישור — נדחית, ובמקומה מוצגים הקטעים עצמם.

## גיבוי ושחזור

```bash
scripts/backup.sh
```

הסקריפט כותב ל-`backups/<timestamp>/` את `rag.dump` (pg_dump בפורמט custom), את `files.tar.gz` (תוכן volume הקבצים) ואת `SHA256SUMS`. התיקייה `backups/` מוחרגת מ-git. שמרו את הגיבויים מחוץ לשרת ובצורה מוצפנת.

שחזור לתוך ה-stack הנוכחי (מוחק ומחליף את מסד `rag` ואת הקבצים):

```bash
scripts/restore.sh backups/<timestamp> --yes
```

מסמכים שנמחקו מחיקה לוגית נשארים בגיבויים עם `deleted_at`, והגישה אליהם נשארת חסומה גם אחרי שחזור. מחיקה סופית של קובץ מהדיסק ומהגיבויים היא פעולה ידנית של מנהל המערכת: מחיקת הקובץ ב-volume (נתיב `<office_id>/<sha256>`) ושמירת גיבויים לפי מדיניות שמירה שמגבילה את משך החזקת הגיבויים הישנים.

## בדיקות

```bash
docker compose up -d db
```

```bash
cd backend && uv run pytest -q
```

הבדיקות רצות מול מסד `rag_test` כמשתמש `rag_app` (בלי עקיפת RLS). בדיקות OCR מדלגות ב-Mac אם ל-Tesseract אין נתוני עברית; הן רצות בתוך ה-image:

```bash
docker run --rm --network appraisal-rag_default -v "$PWD/backend:/app" -w /app -e DATABASE_URL=postgresql+psycopg://rag_app:change-me-app@db:5432/rag_test -e OWNER_DATABASE_URL=postgresql+psycopg://rag_owner:change-me-owner@db:5432/rag_test -e EMBEDDING_PROVIDER=hash appraisal-rag-backend python -m pytest -q -p no:cacheprovider
```

הערכה (מעל 40 שאלות) ובדיקת עומס (10 משתמשים) מול stack רץ עם נתוני דמו:

```bash
cd backend && uv run python scripts/eval.py
```

```bash
cd backend && uv run python scripts/load_test.py
```

בדיקות דפדפן (Playwright, Chromium) מול frontend רץ:

```bash
cd frontend && npx playwright test
```

Frontend:

```bash
cd frontend && npm ci && npm run typecheck && npm run lint && npm run build
```

ה-CI (`.github/workflows/ci.yml`) מריץ lint ובדיקות backend מול pgvector, ובדיקות frontend. הוא לא מעלה מסמכים פרטיים ולא צורך API בתשלום.

## מגבלות ידועות ומה עדיין חסר

- **איכות על שומות אמיתיות לא נבדקה.** לא סופקו מסמכים אמיתיים מורשים. הבדיקות מוכיחות התנהגות תוכנה על נתונים סינתטיים בלבד. הוראות לפיילוט: `docs/evaluation/report.md`.
- **איכות מודל ענן לא נבדקה.** לא הוגדר מפתח; כל בדיקות התוכן רצו מול ה-mock.
- **OCR עברי** (Tesseract `heb`, ‏tessdata_fast) מדויק בטבלאות הסינתטיות, אך מילים קצרות בטקסט רץ נקראות לפעמים כאותיות לטיניות. כל רשומה מעמוד סרוק נכנסת לבדיקה אנושית.
- **DOCX** — אין עמודים פיזיים; ההפניה היא לסעיף ולשורה.
- **פירוש שאלות** מבוסס כללים כשהענן כבוי. ניסוחים שהכללים לא מכירים מקבלים הבהרה ולא תשובה.
- **לא נבנו:** אחסון S3 (קיים ממשק), מתאם OCR ענן, reranker, החלפת מודל embeddings במימד אחר (דורשת migration), איפוס סיסמה עצמי, אינטגרציות, crawler, billing, agents, אפליקציה סלולרית, התאמות שמאיות אוטומטיות, תחומי משפט וביטוח.
