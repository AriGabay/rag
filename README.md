# מנוע ידע למשרדי שמאות (MVP)

מערכת פנימית שבה משרד שמאות מעלה את שומות העבר שלו, והעובדים שואלים בעברית שאלות על הנתונים והשיקולים שבהן. כל תשובה מבוססת רק על מסמכי המשרד שהעובד רשאי לראות, עם הפניה למסמך, לגרסה ולעמוד ב-PDF.

- שאלות מספריות ("מה מחיר למ״ר בחרוזים ב-2024?") מחושבות ב-SQL על כל הרשומות המאומתות, אחרי הבהרה של תנאים שמשנים את התוצאה.
- שאלות תוכן ("מה היו שיקולי השמאי?") נענות מחיפוש משולב בקטעי המסמכים, וכל טענה בתשובה נבדקת מול הקטע שהיא מצטטת.
- שאלות על מאפיינים שאין להם עמודה (ממ״ד, מרפסות, גובה תקרה...) מפורשות לתוכנית מובנית; הנתון מחולץ מהמסמכים עם ציטוט מדויק ומחושב בקוד עם שורת כיסוי (דורש הפעלת ענן למשרד).
- אין חיפוש באינטרנט ואין השלמת עובדות מידע כללי.

כל נתוני הדמו בריפו **סינתטיים** ומסומנים "מסמך סינתטי לדמו". אין להכניס לריפו מסמכים אמיתיים או פרטי לקוחות.

מסמכים נוספים: ארכיטקטורה — `docs/architecture.md`; חוזה API — `docs/api-contract.md`; תוכנית והחלטות — `docs/plans/`; דוח הערכה — `docs/evaluation/report.md`.

## דרישות

- Docker Desktop (Mac) או Docker Engine + Compose v2 (Linux). 6GB RAM לפחות ל-Docker; כ-4GB דיסק פנוי ל-images.
- להרצה מקומית בלי Docker (פיתוח): Python 3.12 + `uv`, Node 22.

## התחלה מהירה (Mac או Linux)

```bash
cp .env.example .env
```

ערכו את `.env` והחליפו את כל הסיסמאות. אחר כך:

```bash
docker compose up -d --build
```

ה-stack כולל: `db` (PostgreSQL 17 + pgvector), `migrate` (Alembic, רץ פעם אחת), `backend` (FastAPI על פורט 8000), `worker` (עיבוד מסמכים) ו-`frontend` (Next.js על פורט 3000). כל הנתונים נשמרים ב-volumes ‏`pgdata` ו-`filedata`, לא בשכבות הקונטיינרים.

טעינת נתוני הדמו (שני משרדים סינתטיים, משתמשים, 16 מסמכים, אישור רשומות שתואמות לנתוני האמת):

```bash
docker compose exec -e OWNER_DATABASE_URL="postgresql+psycopg://rag_owner:<RAG_OWNER_PASSWORD>@db:5432/rag" backend python scripts/seed_demo.py
```

פתחו את http://localhost:3000. משתמשי הדמו (סיסמה: `DEMO_PASSWORD` מ-`.env`, ברירת מחדל `demo1234`):

| משתמש | תפקיד |
|---|---|
| `admin-a@demo.test` | מנהל משרד א |
| `dana@demo.test` | עובדת משרד א, קבוצה 1, רשאית להעלות |
| `yossi@demo.test` | עובד משרד א, קבוצה 2 |
| `admin-b@demo.test` | מנהל משרד ב (לבדיקת בידוד) |

**Linux:** אותן פקודות. אם הדפדפן רץ על מחשב אחר, הפורטים קשורים ל-`127.0.0.1` ב-`docker-compose.yml`; לחשיפה ברשת שימו reverse proxy עם HTTPS לפני השירותים, וקבעו `COOKIE_SECURE=true`.

## שימוש

**העלאה.** מסך "מסמכים": בחרו קבוצת מסמכים וגררו קבצי PDF או DOCX, עד 20 בבת אחת. לכל קובץ מוצגת תוצאה: התקבל, נדחה (עם סיבה), או "כבר הועלה". טבלת הסטטוס מתעדכנת: ממתין, בעיבוד, מוכן, דורש בדיקה, נכשל (עם סיבה, למשל "הקובץ מוגן בסיסמה"). להעלאת גרסה חדשה של מסמך קיים פתחו את פרטי המסמך ובחרו "העלאת גרסה חדשה". הגרסה הקודמת מסומנת "הוחלפה" ויוצאת מהחישובים.

**אישור נתונים.** מסך "בדיקת נתונים": כל רשומה שחולצה מוצגת ליד עמוד המקור ב-PDF. "אשר" מכניס את הרשומה לחישובים; "תקן" דורש ערך והערה, שומר את הערך המקורי ומחשב מחדש מחיר למ״ר; "דחה" מוציא אותה. זוגות חשודים ככפילות מוצגים זה לצד זה עם "מזג" או "השאר נפרד". רק רשומות שאדם אישר או תיקן נכנסות לחישובים.

**שאלה.** מסך "צ׳אט": כתבו שאלה חופשית על כל מידע במסמכים, גם על נושא שאיש לא צפה מראש (למשל "מה גודל ממ״ד ממוצע ברמת גן?"). התשובה היא אחת משלוש: תשובה עם מקורות שאפשר לבדוק, חישוב עם n, שיטה ושורת כיסוי (כמה מסמכים בתחום, בכמה נמצא ערך, כמה לא מציינים, כמה טרם חולצו), או הסבר מה חסר. הבהרה מופיעה רק כשהיא משנה את התוצאה, ואפשר לענות עליה בכפתור או בטקסט חופשי ("התכוונתי לעסקאות"). שאלות המשך כמו "ומה לגבי השנה הקודמת?" משנות רק את מה שנאמר בהן; "עכשיו בנושא אחר: ..." מנקה את התנאים הקודמים. התנאים הפעילים מוצגים כתגיות שאפשר להסיר. "שיחה חדשה" מאפסת את ההקשר.

**בדיקת ערכים שחולצו.** ערך שהמודל חילץ (למשל שטח ממ״ד) נכנס לחישוב רק כ"נתון ראשוני" שמסומן בנפרד, עד שאדם מאשר או מתקן אותו במסך בדיקת הנתונים. ערכים סותרים לאותו נכס עוברים לבדיקה ואינם נספרים.

**פתיחת מקור.** כל מקור בתשובה הוא קישור לקובץ המקורי דרך endpoint מאומת, ישירות לעמוד (`#page=N`). אין גישה לקבצים בנתיב ישיר.

## הפעלת ספק מודל בענן (OpenAI)

כברירת מחדל שום טקסט ממסמכים לא נשלח לספק חיצוני. השימוש בענן מופעל **לכל משרד בנפרד** ורק על ידי מנהל המשרד.

**הגדרה בשרת (`.env`, לעולם לא בקוד ולא ב-git):**

| משתנה | משמעות |
|---|---|
| `LLM_PROVIDER` | `openai` (ברירת מחדל) או `anthropic` |
| `OPENAI_KEY` | מפתח OpenAI. אם הוא ריק נלקח `OPENAI_API_KEY`; אם שניהם מוגדרים — `OPENAI_KEY` קובע |
| `OPENAI_API_KEY` | גיבוי למפתח (השם הסטנדרטי של OpenAI) |
| `OPENAI_MODEL` | ברירת מחדל `gpt-5.4-mini`. המערכת אינה מחליפה מודל בעצמה; מודל אחר נקבע רק כאן |
| `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` | רק כש-`LLM_PROVIDER=anthropic` |
| `DEMO_MODE` | `true` בפיתוח: כשהענן כבוי משיבים בעזרת mock מקומי שמסומן "דמו" |

אחרי שינוי `.env` הריצו `docker compose up -d backend worker`. המפתח מגיע רק לשרת ול-worker; הוא לא מוצג ב-API, בלוגים או בדפדפן (`/api/admin/settings` מחזיר רק `key_present: true/false`).

**הפעלה למשרד:** מסך "ניהול" ← "ספק מודל ענן" ← הפעלה ← אישור שקטעי מסמכים רלוונטיים יישלחו לספק (כולל הערת שמירת הנתונים). לחצו "בדיקת חיבור": קריאה אחת עם טקסט סינתטי קבוע (בלי תוכן של המשרד) שבודקת מפתח, מודל ופלט מובנה. התוצאה נשמרת ומוצגת: `ok`, `missing_key`, `auth`, `model_unavailable`, `timeout`, `rate_limited`, `quota` וכו׳.

**מצבים (`mode`), כפי שהמסך מציג:**

| מצב | מתי | איך נענות שאלות |
|---|---|---|
| `cloud` | הענן מופעל, יש מפתח, ובדיקת החיבור עברה או טרם רצה | המודל מפרש את השאלה לתוכנית מובנית, מחלץ נתונים חדשים עם ציטוט ומנסח תשובה שכל טענה בה נבדקת מול הראיות |
| `error` | הענן מופעל אבל אין מפתח או שבדיקת החיבור נכשלה | תשובות מהמקורות בלבד, עם הסבר מה נכשל. אף פעם לא תשובת mock שנראית אמיתית |
| `demo` | הענן כבוי ו-`DEMO_MODE=true` | mock מקומי, מסומן "דמו" |
| `limited` | הענן כבוי ואין דמו | כללים בלבד: חישובי מחיר ב-SQL, קטעים רלוונטיים לשאלות תוכן, והסבר שחישוב מאפיין חדש (למשל שטח ממ״ד) דורש את המודל או נתונים שנבדקו |

גם במצב `cloud` שאלות מחיר שהכללים מבינים במלואן מחושבות ב-SQL בלי קריאה למודל. למודל נשלחים רק קטעים שהמשתמש מורשה לראות; המודל לא כותב SQL ולא רואה מזהי מסמכים.

**שמירת נתונים:** הבקשות ל-OpenAI נשלחות עם `store=false`. למרות זאת OpenAI עשויה לשמור יומני ניטור שימוש לרעה (abuse monitoring) עד 30 יום, אלא אם לארגון יש הסכם Zero Data Retention. ההערה מוצגת למנהל לפני ההפעלה. אין לשלוח מסמכים אמיתיים לפני שהמשרד אישר זאת.

**אחרי עדכון גרסה עם migration:** הריצו את ה-migrations (`docker compose up -d --build` מריץ את `migrate`), ואז פעם אחת את הסקריפט שמעדכן את ה-chunks הקיימים לכללי החיפוש החדשים (רינדור שורות טבלה, טקסט מנורמל; בלי OCR מחדש, אידמפוטנטי):

```bash
docker compose exec backend python scripts/reindex_text.py
```

## גיבוי ושחזור

```bash
scripts/backup.sh
```

הסקריפט כותב ל-`backups/<timestamp>/` את `rag.dump` (pg_dump בפורמט custom), את `files.tar.gz` (תוכן volume הקבצים) ואת `SHA256SUMS`. התיקייה `backups/` מוחרגת מ-git. שמרו את הגיבויים מחוץ לשרת ובצורה מוצפנת.

שחזור לתוך ה-stack הנוכחי (מוחק ומחליף את מסד `rag` ואת הקבצים):

```bash
scripts/restore.sh backups/<timestamp> --yes
```

מסמכים שנמחקו מחיקה לוגית נשארים בגיבויים עם `deleted_at`, והגישה אליהם נשארת חסומה גם אחרי שחזור. מחיקה סופית של קובץ מהדיסק ומהגיבויים היא פעולה ידנית של מנהל המערכת: מחיקת הקובץ ב-volume (נתיב `<office_id>/<sha256>`) ושמירת גיבויים לפי מדיניות שמירה שמגבילה את משך החזקת הגיבויים הישנים.

## בדיקות

```bash
docker compose up -d db
```

```bash
cd backend && uv run pytest -q
```

הבדיקות רצות מול מסד `rag_test` כמשתמש `rag_app` (בלי עקיפת RLS). בדיקות OCR מדלגות ב-Mac אם ל-Tesseract אין נתוני עברית; הן רצות בתוך ה-image:

```bash
docker run --rm --network appraisal-rag_default -v "$PWD/backend:/app" -w /app -e DATABASE_URL=postgresql+psycopg://rag_app:change-me-app@db:5432/rag_test -e OWNER_DATABASE_URL=postgresql+psycopg://rag_owner:change-me-owner@db:5432/rag_test -e EMBEDDING_PROVIDER=hash appraisal-rag-backend python -m pytest -q -p no:cacheprovider
```

הערכה ובדיקת עומס (10 משתמשים) מול stack רץ עם נתוני דמו. סט ההערכה הקיים (77 תורות, `eval/questions.yaml`) כותב `docs/evaluation/eval-results.md`:

```bash
cd backend && uv run python scripts/eval.py
```

הסט הכללי (61 שאלות על נושאים ומאפיינים שאינם מופיעים בקוד, `eval/questions_general.yaml`) מול ה-stack החי. קורא את התוכניות השמורות דרך התפקיד `rag_app` (‏`RAG_APP_PASSWORD` מ-`.env` או `EVAL_DATABASE_URL`) וכותב JSON עם כל התשובות:

```bash
cd backend && uv run python scripts/eval.py --set general --json /tmp/general.json
```

דגימת מודל אמיתי: דורשת שמשרד א במצב `cloud` (הסקריפט מסרב לרוץ אחרת ואינו משנה הגדרות), שולחת רק את המסמכים הסינתטיים, ממתינה ל-worker כשיש חילוץ ברקע ושואלת שוב, וכותבת `docs/evaluation/real-model-sample.md` (מודל, תאריך, תוצאה לכל פריט, כישלונות וסיבתם, קריאות וטוקנים; בלי מפתחות). `--rescore <json>` מחשב מחדש ציון מתשובות שמורות בלי לשאול:

```bash
cd backend && uv run python scripts/eval.py --set general --real-sample --json /tmp/general-real.json
```

אותו סט רץ גם עם ספק מתוסרט (בלי מודל) בבדיקת הקבלה `tests/acceptance/test_gate8_generality.py`.

```bash
cd backend && uv run python scripts/load_test.py
```

בדיקות דפדפן (Playwright, Chromium) מול frontend רץ:

```bash
cd frontend && npx playwright test
```

Frontend:

```bash
cd frontend && npm ci && npm run typecheck && npm run lint && npm run build
```

ה-CI (`.github/workflows/ci.yml`) מריץ lint ובדיקות backend מול pgvector, ובדיקות frontend. הוא לא מעלה מסמכים פרטיים ולא צורך API בתשלום.

## מגבלות ידועות ומה עדיין חסר

- **איכות על שומות אמיתיות לא נבדקה.** לא סופקו מסמכים אמיתיים מורשים. הבדיקות מוכיחות התנהגות תוכנה על נתונים סינתטיים בלבד. הוראות לפיילוט: `docs/evaluation/report.md`.
- **איכות מודל הענן נמדדה על נתונים סינתטיים בלבד** (`gpt-5.4-mini`, דגימה אחת): עברו 8 מתוך 54 שאלות על נושאים שאינם בקוד (14.8%), הרחק מתחת לסף של 80%. בין הכישלונות: השוואה בין מסמכים שנקראים בשמם, ערכים שחולצו ונדחו בוולידציה, ושתי תשובות שגויות שעברו את האימות. הפירוט ב-`docs/evaluation/real-model-sample.md` וב-`docs/evaluation/report.md`. אין להסיק מהתוצאות על שומות אמיתיות.
- **OCR עברי** (Tesseract `heb`, ‏tessdata_fast) מדויק בטבלאות הסינתטיות, אך מילים קצרות בטקסט רץ נקראות לפעמים כאותיות לטיניות. כל רשומה מעמוד סרוק נכנסת לבדיקה אנושית.
- **DOCX** — אין עמודים פיזיים; ההפניה היא לסעיף ולשורה.
- **פירוש שאלות** מבוסס כללים כשהענן כבוי. ניסוחים שהכללים לא מכירים מקבלים הבהרה או קטעים רלוונטיים, ולא חישוב של מאפיין חדש.
- **לא נבנו:** אחסון S3 (קיים ממשק), מתאם OCR ענן, reranker, החלפת מודל embeddings במימד אחר (דורשת migration), איפוס סיסמה עצמי, אינטגרציות, crawler, billing, agents, אפליקציה סלולרית, התאמות שמאיות אוטומטיות, תחומי משפט וביטוח.
