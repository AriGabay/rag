## How this is scored

Scoring follows the header of `backend/eval/questions_general.yaml` (implemented in `backend/eval/general.py`); wording is never scored. The plan facets (task type, relation, tool) come from the stored turn. A computed figure counts the reviewed figure, else the separately labeled preliminary figure (model-extracted values stay preliminary until a person reviews them). Items that need cloud use off (AE2) cannot run against an office in cloud mode; they are proven by the scripted gate 8 and the U9 tests instead.

## Failure analysis (hand-written, from the stored answers, plans and steps)

Written after the run from the answer JSON, the stored plan and steps of each turn (`questions.plan`, `questions.steps`, read through the runtime role) and, for extraction, the live ledger and facts (read-only `psql`). No code in `backend/app` was changed. Letters: **(a)** interpretation/routing, **(b)** retrieval, **(c)** extraction/validation, **(d)** composition/verification, **(e)** expectation error in the question file (or a scoring rule stricter than the behavior the item is about). The first letter is the primary cause.

### Patterns

1. **Extracted values rarely reach a figure (c), 17 items.** The server puts a model-extracted value into the preliminary figure only when it is validated and unambiguous. In this run most stated values were rejected or routed to review:
   - a key/value table (`מאפיין | פירוט`, `נתון | ערך`) names the attribute only in the row-label cell, so the value cell has no naming term (`attribute_term_not_found`, `quote_not_found`): H5 ceiling height, H1/H5/H7 year built;
   - inner dimensions in cm (H3 `300 על 350 ס״מ`) do not convert to an area (`unit_dimension`);
   - counts written as words (`שתי חניות`, `שתי מרפסות`) are not parsed (`value_not_in_quote`);
   - heights in `מ׳`/`מטר` were stored with `assumed_unit: true` and went to review; plural or synonym naming (`מרפסת` for `שטח המרפסות`, `נבנה בשנת` for year built) goes to review; two balconies in one version are two values, so the version goes to review;
   - text attributes (zoning, planning status, renovation description) are always created as numeric attributes, so no text value is accepted.
2. **Compare cannot name its sides (a), 7 items.** The compare tool runs only on `S#` handles already remembered in the conversation. A new conversation that names two documents by address, or "the two versions", gets a referent clarification (GQ19–GQ21, GQ24, GQ25, GQ27). In a follow-up (GQ22 turn 2) the model picked the handles of H4 and an unrelated document (D6), and the answer labels them as versions.
3. **Locate lists every document with lexical support (b), 7 items.** The locate template lists up to twelve documents that share a query word: the asked document is there, and so are 5–10 irrelevant ones (GQ12–GQ16, GQ50, GQ57). The strict precision rule fails all of them.
4. **The model's claims fail verification and the answer falls back to passages (d), 6 items.** `dropped_claims` ≥ 1 and the limitation "תשובת המודל לא עברה את בדיקות האימות" (GQ01, GQ02, GQ03, GQ08, GQ10, GQ28): the right value is in the retrieved evidence, but the user sees passages instead of an answer.
5. **Task routing (a), 15 items.** Computations planned as `locate` (GQ35, GQ39, GQ56, GQ60) or `answer` (GQ33, GQ48 turns 2–3, GQ49); wrong attribute reuse (GQ34 reused "הבניין הוותיק ביותר"; GQ36 used the balcony area for a balcony count); `compute_explain` instead of `compute` (GQ29, GQ30, GQ32); a generic "average size" mapped to the property area, so the price clarification appeared (GQ53); a new question during a pending clarification read as changing it (GQ52); an invalid plan falling to the limited path (GQ54).
6. **Two wrong answers passed verification (a/b/d).** GQ55 turn 1 answered "the safe room at Irusim 12 is 11.5 m²": the computation averaged H1 (12) and H4v2 (11) because an address is not a filter, and the composer presented the cross-document mean as the apartment's value. GQ61 answered H1's zoning with H2's ("מגורים ב׳", cited to H2): retrieval missed H1 page 2, and the judge accepted a claim that its passage supports but that is about another property.

### Scoring rules corrected after seeing the results

The question file was not edited. The scorer (`backend/eval/general.py`) was corrected where it did not implement the file's header literally; each correction was applied to the same stored answers with `--rescore` (nothing was asked again):

- an `abstain` outcome is "no figure and a matching abstention kind", whatever the answer kind (the composed `not_stated` abstention has kind `content`); an `answer` outcome must carry no abstention kind;
- a `values` entry without a `value` needs only the citation; a value must be stated in a claim citing its document (quoted passages of a fallback are not claims), ignoring house numbers the question itself names ("האירוסים 12" when the value is 12);
- `cleared` accepts a value replaced by the new topic's value; the confirmed conditions of a `truth: records` item include the clarifications it answers;
- a count has no unit.

Before these corrections the same answers scored 5/60 items (held-out 5/54); after them, 8/60 (held-out 8/54).
